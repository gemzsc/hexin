# 校园资源预约系统 V1.4

本目录保存校园资源预约系统任务5的增量版本。V1.4 基于 V1.3 的用户注册、登录、`List<User>` 内存管理和 `user.txt` 文件持久化，新增自定义业务异常，并在程序入口统一展示友好的错误提示。原有用户实体、文件格式和持久化流程继续沿用上一版。

## 功能

- 提供登录、注册和退出菜单；单次操作失败后仍可返回菜单继续使用。
- 使用 `List<User>` 保存运行期的用户对象。注册用户默认为 `student`，注册时间由 `LocalDateTime.now()` 记录。
- 注册时检查用户名、密码非空，密码长度至少为 6 位；拒绝重复用户名和包含文件分隔符 `|` 的输入。
- 用户名首尾空格会被去除；密码按输入原值保存和比较。
- 登录时检查用户名、密码非空，并区分用户不存在、密码错误和登录成功。成功后展示用户名、角色和注册时间，不打印密码。
- 启动时读取 `user.txt`；文件不存在时自动创建。注册成功后追加写入文件，重启程序仍可登录历史用户。
- 读取文件时跳过字段数量不正确、必要字段为空或注册时间格式错误的记录，并输出提示。
- 业务校验失败时抛出自定义异常，由菜单循环统一捕获并显示中文提示；文件读取或保存失败分别显示友好提示。

## 项目结构

```text
task05-v1.4
├─ README.md
└─ src
   ├─ FileUtil.java
   ├─ SystemMain.java
   ├─ User.java
   └─ exception
      ├─ BusinessException.java
      ├─ EmptyParameterException.java
      ├─ PasswordIncorrectException.java
      ├─ UserAlreadyExistsException.java
      └─ UserNotFoundException.java
```

`SystemMain` 负责控制台输入、菜单、注册登录流程和入口异常处理；`User` 只承载用户数据；`FileUtil` 负责创建用户文件、解析记录和追加保存。四种具体业务异常均继承 `BusinessException`，入口捕获父类即可统一展示异常消息。本阶段尚未进行三层架构重构。

## 用户文件格式

`user.txt` 使用 UTF-8 编码，每行保存一名用户，字段顺序如下：

```text
username|password|role|registerTime
```

例如：

```text
alice|abc123|student|2026-10-17T14:30:00
```

时间使用 `LocalDateTime` 的标准文本形式保存和解析。由于竖线 `|` 是字段分隔符，注册时不允许用户名或密码包含该字符。当前版本以明文保存练习数据，不能将此方式用于实际账户安全场景。

`user.txt` 使用相对路径，文件会创建在程序的当前工作目录。使用 IDE 运行时，请确认工作目录设置在本任务目录，避免文件出现在其他位置。

## 环境与运行

需要 JDK 8，无第三方依赖。在 `task05-v1.4` 目录打开终端执行：

```bash
javac -encoding UTF-8 -d out -sourcepath src src/SystemMain.java
java -cp out SystemMain
```

`javac` 会根据 `SystemMain.java` 中的引用，从 `src` 自动编译 `User`、`FileUtil` 和 `exception` 包内需要的类。也可以在 IntelliJ IDEA 中打开本目录并运行 `SystemMain.main`。运行配置的工作目录应设为 `task05-v1.4`。

## 建议验收场景

| 场景 | 预期结果 |
| --- | --- |
| 首次运行且 `user.txt` 不存在 | 自动创建文件，程序正常显示菜单 |
| 注册有效用户名和不少于 6 位的非空密码 | 注册成功，用户记录追加到文件 |
| 退出后重新启动并登录历史用户 | 登录成功，证明文件持久化仍正常 |
| 注册时用户名或密码为空 | 显示对应非空提示，返回菜单，不写入文件 |
| 注册时密码少于 6 位 | 显示密码长度提示，返回菜单 |
| 注册时用户名或密码包含 `|` | 显示分隔符提示，不写入文件 |
| 注册同名用户 | 显示用户名已存在，不追加重复记录 |
| 登录时用户名或密码为空 | 显示对应非空提示，返回菜单 |
| 使用不存在的用户名登录 | 显示用户不存在，不出现空指针异常 |
| 使用已有用户名但输入错误密码 | 显示密码错误，返回菜单 |
| 连续发生业务错误后再正常登录 | 菜单仍可使用，正常登录成功 |
| 文件为空或含单条格式错误记录 | 程序正常启动；错误记录被跳过 |
| 输入未定义的菜单选项 | 显示无效选项并继续显示菜单 |

## 本次设计要点

V1.3 在注册、登录方法中直接打印错误提示，错误处理散落在不同分支。V1.4 用 `BusinessException` 及其子类表达业务失败，由 `main` 的菜单循环捕获并打印 `getMessage()`，因此一次业务失败不会结束程序，也不会向用户展示原生异常堆栈。

业务错误与文件 IO 故障分开处理：用户名重复、用户不存在、密码错误和参数为空属于业务错误；读取或保存文件失败属于 IO 故障。注册时先保存文件，再将用户加入内存集合，避免保存失败后内存中出现未持久化的新用户。`FileUtil` 继续使用 try-with-resources 自动关闭字符流。

本版本保留控制台结构，为后续迭代逐步重构留下空间。
