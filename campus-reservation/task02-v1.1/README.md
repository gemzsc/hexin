# 校园资源预约系统 V1.1

本目录保存校园资源预约系统的第二个增量版本。V1.1 从 V1.0 的固定账号登录程序继续开发，加入注册菜单、内存用户集合和输入校验。当前版本用于练习控制台交互、集合查找与单一职责，不包含文件持久化。

## 功能

- 提供登录、注册和退出菜单，操作后返回菜单。
- 使用 `HashMap<String, String>` 在程序运行期间保存用户名和密码。
- 注册时检查用户名非空、密码非空且长度至少为 6 位，并拒绝重复用户名。
- 登录时检查用户是否存在及密码是否匹配；成功后以学生身份提示。
- 用户名首尾空格会被去除，密码按输入原值保存和比较。

用户数据只保存在内存中，退出程序后不会保留；这是后续文件持久化迭代前的预期行为。当前注册流程只创建学生账号，不提供管理员注册入口。

## 环境与运行

需要 JDK 8。源码位于 `src/SystemMain.java`。在本目录打开终端执行：

```bash
javac -encoding UTF-8 -d out src/SystemMain.java
java -cp out SystemMain
```

也可以在 IntelliJ IDEA 中打开本目录并运行 `SystemMain.main`。

## 建议验收场景

| 场景 | 预期结果 |
| --- | --- |
| 注册有效用户名和不少于 6 位的非空密码 | 注册成功 |
| 注册空用户名或全空格用户名 | 提示用户名不能为空 |
| 注册空密码、全空格密码或少于 6 位密码 | 提示密码不合法 |
| 再次注册同一用户名 | 提示用户名已存在，原密码不被覆盖 |
| 使用刚注册的用户名和密码登录 | 学生登录成功 |
| 使用已注册用户名和错误密码登录 | 提示密码错误 |
| 使用未注册用户名登录 | 提示用户不存在 |
| 输入未定义的菜单选项 | 提示无效选项并继续显示菜单 |
| 退出后重新启动 | 用户集合为空，需重新注册 |

## 本次设计要点

用户集合在菜单循环外创建，使注册、登录共享同一份运行期数据。注册前使用 `containsKey` 查重，避免 `put` 覆盖已有用户。用户名和密码校验抽取为独立方法，主流程负责交互和分支，校验方法负责判断输入是否合法。当前版本尚未引入实体类、分层架构或文件读写，后续任务将逐步演进。
