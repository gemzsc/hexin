# 校园资源预约系统 V1.3

本目录保存校园资源预约系统任务4的增量版本。V1.3 基于 V1.2 的用户注册、登录和 `List<User>` 内存管理，新增 `FileUtil` 与 `user.txt` 文件持久化：程序启动时加载历史用户，注册成功后追加保存。用户实体和既有交互流程继续沿用上一版。

## 功能

- 提供登录、注册和退出菜单，操作后返回菜单。
- 使用 `List<User>` 保存当前运行期的用户对象；用户字段为用户名、密码、角色和注册时间。
- 注册时检查用户名非空、密码非空且长度至少为 6 位，并拒绝重复用户名。
- 用户名首尾空格会被去除；密码按输入原值保存和比较。
- 注册用户默认为 `student`，注册时间由 `LocalDateTime.now()` 记录。
- 登录时区分用户不存在、密码错误和登录成功；成功后展示用户名、角色和注册时间，不打印密码。
- 启动时读取 `user.txt`；文件不存在时自动创建。
- 新用户注册成功后追加写入 `user.txt`。程序重启后仍可加载并登录历史用户。
- 读取文件时跳过字段数量不正确、必要字段为空或注册时间格式错误的记录，并输出提示。

## 项目结构

```text
task04-v1.3
├─ README.md
└─ src
   ├─ FileUtil.java
   ├─ SystemMain.java
   └─ User.java
```

`SystemMain` 负责控制台输入、菜单和用户流程；`User` 只承载用户数据；`FileUtil` 负责创建用户文件、解析用户记录和追加保存用户。

## 用户文件格式

`user.txt` 使用 UTF-8 编码，每行保存一名用户，字段顺序如下：

```text
username|password|role|registerTime
```

例如：

```text
alice|abc123|student|2026-10-17T14:30:00
```

时间使用 `LocalDateTime` 的标准文本形式保存和解析。由于竖线 `|` 是字段分隔符，注册时不允许用户名或密码包含该字符。当前版本以明文保存练习数据，不能将此方式用于实际账户安全场景。

`user.txt` 使用相对路径，文件会创建在程序的当前工作目录。使用 IDE 运行时，请确认工作目录设置在本任务目录，避免文件出现在其他位置。

## 环境与运行

需要 JDK 8，无第三方依赖。在本目录打开终端执行：

```bash
javac -encoding UTF-8 -d out src/SystemMain.java src/User.java src/FileUtil.java
java -cp out SystemMain
```

也可以在 IntelliJ IDEA 中打开本目录并运行 `SystemMain.main`。确保运行配置的工作目录是 `task04-v1.3`，这样 `user.txt` 会保存在该目录下。

## 建议验收场景

| 场景 | 预期结果 |
| --- | --- |
| 首次运行且 `user.txt` 不存在 | 自动创建文件，程序正常显示菜单 |
| 注册有效用户名和不少于 6 位的非空密码 | 注册成功，用户记录追加到文件 |
| 使用刚注册的用户登录 | 登录成功，显示用户名、student 角色和注册时间，不展示密码 |
| 退出后重新启动并登录历史用户 | 登录成功，证明启动加载和文件持久化有效 |
| 注册同名用户 | 提示用户名已存在，不覆盖原记录 |
| 文件为空 | 正常启动，用户集合为空 |
| 文件中存在格式错误的记录 | 提示并跳过错误记录，其余有效记录仍可加载 |
| 使用已注册用户名但输入错误密码 | 提示密码错误 |
| 使用不存在的用户名登录 | 提示用户不存在，不出现空指针异常 |
| 输入未定义的菜单选项 | 提示无效选项并继续显示菜单 |

## 本次设计要点

V1.2 的用户集合只存在于内存中。V1.3 启动时由 `FileUtil.loadUsers()` 读取文件并重建集合；注册时由 `FileUtil.saveUser()` 追加记录，保存成功后再加入内存集合并提示成功。文件读写集中在工具类中，`SystemMain` 不直接管理 IO 流，降低交互流程与持久化细节的耦合。

文件使用逐行文本格式，便于查看和调试；代价是需要保持字段顺序一致，并处理分隔符和格式错误。`FileUtil` 使用 try-with-resources 关闭字符流，避免资源未释放。

本版本仍未引入三层架构、数据库或自定义异常体系。用户信息文件中的密码为明文，仅用于课程练习。
